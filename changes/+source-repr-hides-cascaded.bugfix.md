`repr(source)` no longer shows fields the load/config cascade filled in — only what the caller actually set on the source. Previously, any optional field left `None` on a source (e.g. `EnvSource(prefix="APP_")`) picked up `load()`/`config` defaults (`expand_env_vars`, `nested_resolve_strategy`, `strict`, …) before `__repr__` ran, so those cascade-filled values leaked into user-facing error messages (`"Config value '...' was unused (from EnvSource(expand_env_vars='default', ...))"`) even though the caller never wrote them. `strict` had a one-off `repr=False` band-aid for its own symptom; it's now a normal, visible field like the rest.
