Fixed a pre-existing bug, unrelated to `default_factory`, where adding any field validator to a schema broke loading a valid config whose fields were split across multiple sources: a nested section not itself targeted by a validator was still constructed as a real instance from each source's partial raw data during the per-source field pass, so a subfield present only in another source was reported as missing. Only the specific nested dataclass types a validator is directly attached to (via `Annotated[...]` on the field or one of its ancestors) are still constructed for real during the field pass; every other nested section can again be freely split across sources. Sections a validator directly targets remain unsplittable across sources, since the validator needs a real instance rather than a partial dict.
